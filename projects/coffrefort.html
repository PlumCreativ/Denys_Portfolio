CryptoVault

Coffre-fort numérique sécurisé — Backend REST PHP + Client desktop JavaFX — Projet BTS SIO SLAM

Vue d'ensemble

CryptoVault est un système complet de coffre-fort numérique sécurisé composé de deux parties complémentaires : un backend REST PHP assurant le stockage chiffré des fichiers, et un client desktop JavaFX offrant une interface native multi-plateforme pour gérer l'espace de stockage.

Le projet met en œuvre des techniques avancées de sécurité : chiffrement AES-256-GCM au repos avec enveloppe de clés, authentification JWT, versionnage automatique des fichiers, partages sécurisés avec tokens signés et audit complet des accès.

Backend — API REST PHP

L'API REST est construite avec Slim Framework 4.12 et Medoo 2.2 et expose 38 routes couvrant l'ensemble des opérations métier.

  • Chiffrement AES-256-GCM au repos avec enveloppe de clés (KEK)
  • Authentification JWT via Firebase PHP-JWT avec middleware dédié
  • Organisation hiérarchique des dossiers avec contraintes CASCADE
  • Versionnage automatique : checksum SHA-256, IV et auth tag par version
  • Partages sécurisés : token base64url, expiration, limitation d'usages, révocation
  • Gestion des quotas utilisateur avec blocage automatique à 100 %
  • Table audit_logs pour traçabilité complète (IP, user-agent, action)
  • Rôle administrateur : gestion des utilisateurs, suppression avec nettoyage CASCADE

Client — Application Desktop JavaFX

Le client lourd JavaFX 21 communique avec l'API REST via OkHttp 4.12 et offre une interface native réactive.

  • Connexion sécurisée avec surveillance automatique de session JWT (toutes les minutes)
  • Déconnexion automatique à l'expiration du token avec redirection
  • Arborescence hiérarchique de dossiers (TreeView) avec menu contextuel
  • Upload / download avec barre de progression, support fichiers volumineux (streaming)
  • Historique complet des versions : checksum SHA-256, téléchargement sélectif
  • Gestion des partages : création, expiration, limitation d'usages, révocation
  • Barre de quota avec alertes visuelles à 80 % (orange) et 90 % (rouge)
  • Panneau d'administration : gestion des quotas et des utilisateurs

Architecture

Les deux composants suivent le pattern MVC. L'API REST utilise des Repositories Medoo en couche d'accès aux données ; le client JavaFX sépare les vues FXML, les contrôleurs annotés @FXML et les modèles POJO mappés via Jackson.

  • Backend : AppFactory Slim → Middlewares (CORS, JWT, Error) → Routes → Controllers → Repositories → Medoo → MySQL
  • Client : Interface FXML → Contrôleur @FXML → ApiClient (OkHttp) → API REST
  • Stockage physique chiffré dans storage/files/{user_id}/
  • Base de données avec triggers et contraintes CASCADE complètes

Sécurité

  • Chiffrement AES-256-GCM : chaque version de fichier possède son propre IV et auth tag
  • Enveloppe de clés : la clé de chiffrement est elle-même chiffrée avec une KEK (Key Encryption Key)
  • Tokens JWT : vérification d'expiration côté client et côté serveur, renouvellement automatique
  • Hachage des mots de passe : password_hash() / password_verify()
  • Tokens de partage : base64url (~43 caractères), non devinables
  • Interdiction de supprimer la dernière version d'un fichier
  • Protection contre l'auto-suppression administrateur
